# Domain docs

Use a single-context layout:
- `GLOSSARY.md` at the repository root
- `docs/adr/` for architecture decision records

Read ROADMAP.md first, then the glossary and relevant ADRs before
exploring or designing the affected area.

If the glossary or ADRs are absent, continue silently. Create them
through domain-modeling when terms or decisions are actually resolved.

Use glossary terms consistently in issues, designs, code and tests.
Surface conflicts with existing ADRs explicitly for resolution.
Detailed safety contracts retain the authority described in ROADMAP.md.
